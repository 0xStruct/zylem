1

Open a Ring

A Ring is one file holding 4,096 consecutive Zcash blocks, about a day of the chain, packaged so any website can host it. Inside are the block headers, every transaction in the compact form wallets already download, short digests that let each transaction's ID be rebuilt, and the state the Ring starts from.

In about a minute you will check 4,096 real Zcash blocks in this browser and catch a server trying to fake a payment.

2

Check the whole Ring

The full client check, block by block. This is what lets any mirror, CDN or stranger host Rings: a client accepts nothing it cannot rebuild.

Opens after step 1.

  • Every header has a valid Equihash solution, meets its own target and links to the one before; the difficulty and time rules apply once 113 earlier headers are known.
  • Every transaction ID is rebuilt from the compact data and digests, and the IDs reproduce each header's Merkle root.
  • The history tree, replayed block by block, matches what every following header commits to, which authenticates each block's tree roots.
  • The Ring's note commitments, appended to its starting tree state, reproduce those authenticated roots, so every tree state inside is authenticated too.

You rely on the cryptography and the code running in this tab, not on the host that served the file.

4

Try to lie

Each button makes a copy of the open Ring altered the way a dishonest server would, then runs the step 2 check on it. The server would also publish a matching file hash, so only verification can catch it. The target follows the block opened in step 1; any transaction works.

Swaps the starting Ironwood tree for another of the same size, so a wallet would build unspendable anchors.

5

Verify succinct proof on mobile and on-chain

A succinct proof of Zcash data stays small and quick to check however many blocks it covers. One SP1 proof states that every header in a range passed Equihash, its target and the difficulty rules, and commits to a 104-byte record of each block. Wrapped in Groth16, the whole claim fits in 356 bytes that a phone and a smart contract both verify.

Opens after step 4.

On mobile and on-chain

356 bytes

The proof wrapped in Groth16 over BN254. This browser verifies it in a few hundred ms, and SP1's own verifier contract accepted these exact bytes in a local EVM for about 304,000 gas. No contract is deployed on a chain yet. Its one extra assumption is SP1's Groth16 trusted setup.

Without a trusted setup

1.27 MB

The compressed STARK the wrap is made from. It needs no trusted setup and verifies here in a few dozen ms, for clients that want the fewest assumptions.

Light wallet vs Zylem

Don't trust, verify

Today's Zcash light wallets download compact blocks from a light-wallet server and take them as given. Zylem gives the same wallets data they can check. Steps 2 to 5 above are the checks in the Zylem columns, run on this page.
